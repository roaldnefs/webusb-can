Quick start

1. Get on a bus

In the top bar, either:

  • Connect device: attach a gs_usb / candleLight / CANable adapter and pick a bitrate first.
  • Start simulator: run an in-browser virtual car. No hardware needed.

2. Watch traffic

  • Log: every frame, in arrival order. Click a row to copy its data hex.
  • Sniffer: one row per CAN ID, with cycle time and bytes that flash when they change. Best for finding the ID that drives a behavior.
  • Use the RX / TX / UDS filters and the ID filter to narrow down.

3. Send frames

  • The send bar at the bottom: type a hex ID and data bytes, hit Send for one frame or Repeat to send periodically.
  • Signals tab: saved periodic senders you can switch on and off.

4. Brute force / fuzz

Fuzzer tab: cangen-style. Pick random, increment, or fixed for ID, DLC, and data; set a gap and (optionally) a count, then Start fuzzing.

5. UDS / diagnostics

UDS tab: request and response IDs (default 7E0/7E8) and hex request bytes, with built-in ISO-TP transport and NRC name decoding. Tester present keeps extended sessions alive. The simulator has an ECU to talk to: try 22 F1 90 to read its VIN.

6. Drive the simulator

  • The simulated car window floats over the log. Drag its title bar to move it.
  • Its buttons are the driver's controls: the simulated car broadcasts the result on the bus, so those frames appear as RX. Anything you send yourself appears as TX and drives the cluster the same way.
  • Bogus traffic adds unrelated IDs to make the puzzle harder. Turn it off for a clean demo.

7. Script from the console

Open DevTools (F12) and drive everything via window.api:

  • api.send({id: 0x244, data: [0,0,0,0x19,0,0,0,0]}): send one frame.
  • const off = api.onAnyFrame(f => console.log(f.id.toString(16), f.data)); off(): tap RX traffic.
  • api.simulator.start(); api.simulator.accel(true): drive the cluster without buttons.

Full reference: README, Console API.
